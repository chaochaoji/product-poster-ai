# Product AI 设计决策记录

## 第一题：商品属性识别与卖点提炼

### 架构：LangGraph 多 Agent

```
📸 商品图片
    │
    ▼
┌───────────────────────┐
│ Agent 1（1次多模态）    │  ← 图片只发一次
│ 客观任务：              │
│ → 分类 + 商品名        │
│ → 5-8个结构化卖点      │
│ → visual_description  │  ← 备用字段，暂不启用
└───────────┬───────────┘
            │ 纯文本输入
   ┌────────┼────────┐
   ▼        ▼        ▼
┌──────┐┌──────┐┌──────┐
│淘宝   ││京东   ││抖音   │  ← 3个纯文本Agent并发
│促销导购││专业测评││种草博主│     互斥人格+禁词表
└──────┘└──────┘└──────┘
   └────────┼────────┘
            ▼
        完整 JSON
```

### 拆分原则

- **看图的合并**：分类、商品名、卖点、外观描述共享一个视角（客观描述），1次多模态
- **写文案的拆分**：淘宝/京东/抖音需要互斥人格，3个Agent并发执行

### 平台文案风格锁定

三层锁死，不用少样本：

1. **人设角色**：淘宝=促销导购，京东=专业测评师，抖音=生活方式博主
2. **句式+关键词库**：每个Agent有专属句式模板和必用关键词
3. **互斥禁词表**：淘宝禁用"参数/正品/SGS"，京东禁用"限时/抢购/手慢无"，抖音禁用"SGS/性价比"

### 卖点质量保证

- System Prompt 要求 5-8 个卖点，覆盖至少 5 个维度类别
- 六维度：材质成分 / 功能功效 / 设计外观 / 工艺技术 / 适用场景人群 / 规格参数
- 每个类别最多 2 个卖点
- Few-shot：正确示例（具体数据+工艺）和错误示例（空洞描述）
- 禁止词列表

### visual_description 字段（保留）

- 商品主体外观客观描述（30-100字）
- 仅视觉形态特征，不含卖点评价
- **当前暂不使用**，与参考图模式对比后再定

## 第二题：参数化生图提示词生成

### 架构：Mapper + Agent + KB

```
Task1 JSON + usage_type + platform
         │
         ▼
   ParameterMapper（纯代码）        确定性映射，查表计算
   ├── 材质→反射参数
   ├── 用途→构图约束
   ├── 品类→场景风格
   └── 平台→视觉风格
         │
    8个模块的结构化参数
         │
         ▼
   知识库查询（prompt_kb.py）      品类+平台参考条目
         │
         ▼
   Agent: 提示词合成（LLM）         创造性工作，自然语言
   ├── System Prompt 内置质量约束
   ├── 品类风格 + 平台风格 自然融合
   ├── 知识库参考注入
   └── 输出完整生图提示词
         │
         ▼
   完整提示词 → 即梦 API → 生图 → Pillow叠文案（卖点图）
```

### 为什么代码+LLM组合

| | 纯代码 | 纯LLM | 代码+LLM |
|---|---|---|---|
| 映射准确性 | ✅ | ❌ 可能错 | ✅ |
| 语言流畅度 | ❌ 机械 | ✅ | ✅ |
| 平台风格融合 | ❌ 拼接 | ✅ 自然融入 | ✅ |

### 知识库方案

**一个 Python dict 文件**（`prompt_kb.py`），不是向量数据库：

- 规模：9品类 × 3用途 × 3平台 ≈ 最多81条
- 查询：精确匹配 → 模糊回退
- 新增品类：加一个 dict 条目
- 内容：style_ref / lighting_tip / composition / example / negative_hint

### 三层知识注入

```
第一层：少样本（System Prompt内嵌）     保底，覆盖主品类
第二层：知识字典（prompt_kb.py）        核心，可积累维护
第三层：联网搜索                       兜底，未知品类触发
```

### 8模块结构

| 模块 | 来源 | 说明 |
|------|------|------|
| 主体描述 | category + product_name + visual_desc | 参考图模式优先 |
| 焦距镜头 | usage_type | 主图85mm全景深/场景50mm浅景深/卖点70mm均衡 |
| 布光方案 | usage_type + platform | 平台卖点图覆盖布光风格 |
| 材质反射 | category + 材质推断 | 18种材质映射表 |
| 构图约束 | usage_type | 主图居中/场景三分/卖点分区 |
| 背景环境 | usage_type + category + platform | 三层叠加 |
| 风格指令 | category + platform | 品类风格 + 平台风格融合 |
| 营销布局 | usage_type + platform | 卖点图右侧留白+Pillow叠文 |

### 参考图模式

- 原图 base64 传入即梦 `image` 参数
- 参考模式下 prompt 强调"保持参考图主体不变"
- 卖点图 prompt 明确"商品左侧55-60%，右侧纯色留白"

### 质量约束

四类约束直写进提示词合成Agent的System Prompt，不另设审核Agent：

1. **商品主体**：完整保留/未色偏/占比≥40%(主图)或25%(场/卖)/视觉焦点
2. **背景环境**：品类匹配/不抢焦点/场景图真实场景感/禁纯色块假阴影
3. **布光质感**：材质匹配合适反射/光源方向一致/禁矛盾阴影
4. **画面质量**：无畸变/无乱码/边缘清晰/构图准确

### 前端交互

```
Step 2: 生成提示词              Step 3: AI 出图
┌───────────────────────┐      ┌──────────────┐
│ 用途：[主图][场景][卖点]│      │              │
│ 平台：[通用][淘宝][京东][抖音]│ → │ [生成图片]    │
│ [生成提示词]            │      │              │
└───────────────────────┘      └──────────────┘
```
平台选择在Step2触发提示词风格变化，Step3仅执行生图。

## 框架选型

- **LangGraph** 实现多 Agent 编排
- State 管理全流程状态流转
- 三个文案Agent并发、提示词合成Agent独立
- API：1次多模态（豆包）+ 3次文本并发（文案）+ 1次文本（提示词合成）+ 1次生图（即梦）
